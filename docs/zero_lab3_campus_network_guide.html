Six Interacting Subsystems
// ZERO INSIGHT

The module isn't just about three protocols — it's about six interdependent layers of decision-making: how to number, segment, route, assign addresses, control access, and verify a network. Each subsystem fails independently and debugging requires knowing which layer is responsible.

IP Addressing & Subnetting SUBSYSTEM 1 ▶

Role: Assigns unique logical addresses to every interface and host. Without correct subnetting, nothing routes.

Devices/Actors: Router interfaces, LAN PCs, DHCP server

Key parameters: Subnet mask, network address, broadcast address, host range

Purpose: Divide the address space to fit each department's host count using VLSM — no wasted IPs, no overlap.

Key checks: Can R1's LAN PC ping R1's interface? Are all /30 WAN links in different subnets?

// WHY THIS MATTERS

All three routing methods in Lab 3 assume correct IP addressing. A misconfigured subnet mask is invisible to routing protocols — the router will advertise the wrong network and traffic will silently drop.

Static Routing Engine SUBSYSTEM 2 ▶

Role: Operator-defined forwarding decisions. Every destination network must be explicitly entered.

Devices/Actors: Network administrator, router routing table

Key parameters: Destination network, subnet mask, next-hop IP or exit interface

Purpose: Establish baseline full connectivity before dynamic protocols are tested. Also used to measure manual configuration time.

Key checks: show ip route — are all 4 LAN networks present on every router? Does pinging across all LANs succeed?

ip route 192.168.2.0 255.255.255.0 10.0.12.2IOS CLI
RIP v2 Distance-Vector Engine SUBSYSTEM 3 ▶

Role: Routers share routing tables every 30 seconds. Best path = fewest hops.

Devices/Actors: All 4 routers, RIP process

Key parameters: Version 2, no auto-summary, network statements, hop count metric

Purpose: Measure automatic convergence after a link failure — how long before traffic finds an alternate path?

Key checks: show ip rip database — are all networks learned? After shut on R1-R2 link, how many seconds until ping recovers?

router rip version 2 no auto-summary network 192.168.1.0 network 10.0.0.0IOS CLI
OSPF Link-State Engine SUBSYSTEM 4 ▶

Role: Each router builds a full map of the network (LSDB). SPF algorithm computes shortest cost path.

Devices/Actors: All 4 routers, OSPF process, DR/BDR election (if applicable)

Key parameters: Process ID, area 0, network statements with wildcard masks, router-id

Purpose: Measure fast convergence and routing efficiency — OSPF reacts to topology changes in seconds, not minutes.

Key checks: show ip ospf neighbor — are adjacencies FULL? show ip ospf database — is the LSDB consistent across all routers?

router ospf 1 router-id 1.1.1.1 network 192.168.1.0 0.0.0.255 area 0 network 10.0.12.0 0.0.0.3 area 0IOS CLI
VLAN & Inter-VLAN Routing SUBSYSTEM 5 ▶

Role: VLANs isolate broadcast domains on switches. Inter-VLAN routing allows controlled communication between them.

Devices/Actors: Layer 2 switches, router or Layer 3 switch, trunk links

Key parameters: VLAN IDs, trunk ports (802.1Q), sub-interfaces or SVI, encapsulation

Purpose: Segment the campus network so Engineering, ICT, Admin, Students, and Servers are logically separated but can still communicate as permitted.

Key checks: Can VLAN 10 ping VLAN 50? Is VLAN 40 blocked from reaching VLAN 30? Are trunks active?

interface GigabitEthernet0/0.10 encapsulation dot1Q 10 ip address 192.168.10.1 255.255.255.0Router-on-a-stick
Network Services & Security (DHCP + ACLs) SUBSYSTEM 6 ▶

Role: DHCP automates IP assignment. ACLs enforce the security policy: students reach servers, not admin.

Devices/Actors: DHCP server or router, ACL entries on router interfaces

Key parameters: DHCP pool, default-router, DNS server, ACL permit/deny statements, interface direction (in/out)

Purpose: Simulate a production environment where dynamic clients are managed and traffic is filtered at the network boundary.

Key checks: Do VLAN 40 hosts get IPs automatically? Does a VLAN 40 PC fail to ping 192.168.30.x? Does the same PC successfully ping 192.168.50.x?

ip access-list extended STUDENT-POLICY deny ip 192.168.40.0 0.0.0.255 192.168.30.0 0.0.0.255 permit ip 192.168.40.0 0.0.0.255 192.168.50.0 0.0.0.255ACL example
Seven Foundational Assumptions

These must be true in your mental model before you configure anything. Click each to reveal the explanation and self-assessment question.

P1Routers forward packets between networks using routing tables▶

A router is not a switch. It operates at Layer 3 and makes per-packet forwarding decisions based on the destination IP address, consulting its routing table to find the best next-hop. Without a routing table entry, the packet is dropped.

PCs on a LAN only know their default gateway — they hand all non-local traffic to the router's interface address on their subnet.

Self-check: Can you trace how a packet from 192.168.1.10 reaches 192.168.4.10 via two intermediate routers, naming the routing table lookups at each hop?
P2Subnets must not overlap; each interface belongs to exactly one subnet▶

If two router interfaces share a subnet, the router gets confused about which interface to use for outbound traffic. WAN links use /30 subnets (4 addresses, 2 usable) to minimise waste. LAN segments use /24 for up to 254 hosts.

Self-check: Given 10.0.0.0/24, can you carve out four /30 subnets for WAN links and list their network, usable hosts, and broadcast addresses?
P3Convergence time is the interval between a failure and restored routing stability▶

When a link fails, routers must detect the failure, propagate the update, and recalculate routes. During this window, packets may be lost or looped. Measuring this window is the primary metric in Lab 3's failure simulation.

Static routing never converges automatically. RIP takes 30–180 seconds (periodic updates + holddown timers). OSPF typically converges in under 10 seconds.

Self-check: If RIP sends updates every 30 seconds and uses a 180-second holddown timer, what is the worst-case convergence time after a link failure?
P4VLANs are logical, not physical — a trunk carries multiple VLANs on one cable▶

A VLAN creates a separate broadcast domain on a physical switch. Hosts in different VLANs cannot communicate without a Layer 3 device (router or L3 switch). An 802.1Q trunk port tags each frame with the VLAN ID, allowing a single physical link to carry traffic from all VLANs to a router.

Self-check: If you add a host to VLAN 20 on a switch port but forget to configure the router sub-interface for VLAN 20, can that host reach VLAN 10? Why or why not?
P5ACLs are stateless and directional — you must know where to apply them▶

An ACL is a list of permit/deny rules matched sequentially against packet headers. It does not track sessions. The classic rule: standard ACLs (match source IP only) go close to the destination; extended ACLs (match src+dst+protocol) go close to the source. Applied inbound filters traffic entering the interface; outbound filters traffic leaving.

Self-check: You want to block VLAN 40 from reaching VLAN 30 but allow it to reach VLAN 50. Write the ACL logic (permit/deny lines) and identify which interface and direction to apply it.
P6OSPF uses cost, not hops — bandwidth determines the best path▶

OSPF cost = reference bandwidth (100 Mbps default) divided by interface bandwidth. A FastEthernet link has cost 1; a 10 Mbps link has cost 10. OSPF always picks the lowest total-cost path, which usually means the highest-bandwidth path — unlike RIP which just counts router hops.

Self-check: Two paths from R1 to R4: Path A is 2 hops over FastEthernet (cost 1 each). Path B is 1 hop over 10 Mbps Ethernet (cost 10). Which does OSPF prefer? Which does RIP prefer?
P7DHCP requires a relay agent if the server is on a different subnet▶

DHCP discovery messages are broadcasts — they don't cross router boundaries. If your DHCP server is in VLAN 50 but clients are in VLANs 10–40, you must configure ip helper-address on each router sub-interface to forward DHCP requests to the server's unicast address.

Self-check: A student in VLAN 40 sends a DHCP discover. The DHCP server is in VLAN 50. List the exact configuration line you'd add to the VLAN 40 sub-interface to make DHCP work.

Key Terms
Routing TableRIB
A database in a router listing known destination networks, the next-hop address to reach them, and the metric/administrative distance of the route.
In Lab 3: "show ip route" on R1 shows C (connected), S (static), R (RIP), or O (OSPF) routes.
Convergence
The process by which all routers in a network reach a consistent, accurate view of the topology after a change such as a link failure.
After shutting R1–R2 WAN: RIP converges in ~90–180s; OSPF converges in <10s.
Distance VectorDV
A routing protocol class where each router knows only the distance (metric) to destinations and the direction (vector/next-hop) to reach them — not the full network map.
RIP v2 is distance-vector: each router shares its routing table with neighbors every 30 seconds.
Link StateLS
A routing protocol class where each router builds a complete map of the network topology (LSDB) and runs Dijkstra's SPF algorithm to find the shortest-cost path to every destination.
OSPF is link-state: every router in area 0 has an identical LSDB ("show ip ospf database").
OSPF Cost
OSPF's metric = reference bandwidth (100 Mbps default) divided by interface bandwidth. Lower cost = preferred path.
A FastEthernet (100 Mbps) link has cost 1. A 10 Mbps link has cost 10. OSPF prefers the FastEthernet path.
VLANVirtual LAN
A logical grouping of switch ports into separate broadcast domains, regardless of physical location. Traffic between VLANs requires Layer 3 routing.
Campus: VLAN 30 (Admin) and VLAN 40 (Students) are on the same switch but cannot communicate without going through the router — where the ACL blocks it.
802.1Q Trunk
A switch-to-switch or switch-to-router link that carries traffic from multiple VLANs. Each frame is tagged with a 4-byte VLAN ID header.
The link from the core switch to the router carries VLANs 10, 20, 30, 40, 50 simultaneously on one cable.
ACLAccess Control List
An ordered list of permit/deny rules applied to a router interface. Rules are matched top-to-bottom; the first match wins. An implicit deny all sits at the end.
STUDENT-POLICY: deny 40→30, permit 40→50, permit any — applied inbound on the VLAN 40 sub-interface.
DHCPDynamic Host Config Protocol
A protocol where a server automatically assigns IP address, subnet mask, default gateway, and DNS to clients on a network.
Students in VLAN 40 receive 192.168.40.x automatically; ip helper-address forwards the broadcast request to the server in VLAN 50.
Router-on-a-StickRoaS
A single physical router interface subdivided into logical sub-interfaces, each assigned to a different VLAN. The physical link is a trunk. Used for inter-VLAN routing without a Layer 3 switch.
Gi0/0.10 handles VLAN 10, Gi0/0.20 handles VLAN 20 — all on the same physical cable to the switch.
VLSMVariable Length Subnet Mask
Technique to subdivide an IP address space into subnets of different sizes, each sized to match its segment's host requirements — minimising address waste.
A /24 for 200-host Engineering VLAN; a /30 for a 2-host WAN link. Both carved from the same address space.
